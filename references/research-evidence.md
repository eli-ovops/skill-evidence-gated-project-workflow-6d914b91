# 研究证据与判断

## 适用范围

用于市场/行业/公司/产品/方案研究，既有报告审查，以及会影响投入、采购、架构或路线的重要判断。轻量事实查询按任务风险缩减，不强制建立完整台账。

## 任务框架

研究前确认：

- 对象及唯一身份；
- 用户要做的决定，而非泛泛“了解”；
- 受众、范围与排除项；
- 参考日期和允许的数据时效；
- 可用来源、隐私边界和停止条件；
- 结论需要达到的证据层级。

对象或目的的歧义会改变方法时，只问 1–3 个关键问题。

## 证据对象

每项重要内容使用稳定 ID：

```yaml
claim: {id: CLM-001, statement: "待验证主张", status: open}
source: {id: SRC-001, path_or_url: "...", title: "...", published_at: "...", retrieved_at: "...", scope: "..."}
fact: {id: FACT-001, type: observed|calculated|inferred, statement: "...", source_ids: [SRC-001], claim_ids: [CLM-001]}
```

来源等级只描述直接性，不自动等于可信度：

- A：原始数据、源代码、合同、标准、监管或实际测试结果；
- B：权威机构、同行评审、成熟供应商技术文档；
- C：媒体、社区、招聘、用户反馈等交叉线索。

营销材料即使是一手来源，也只能证明其公开主张，不能证明实际运行效果。

## 判断卡

```yaml
statement: "完整判断句"
scope: "主体、时间和成立条件"
supporting_fact_ids: [FACT-001]
counterevidence_fact_ids: []
reasoning: "证据如何支持判断"
confidence: high|medium|low
confidence_basis: "直接性、时效、数量和冲突"
invalidation_conditions: ["什么新事实会推翻结论"]
decision_impact: "会改变什么行动"
```

没有找到反证不等于不存在反证；记录搜索边界和残余风险。

## 数据健康度

按身份、时间、范围、机制、成本、竞争/依赖、安全/隐私及用户目的分别标记：

`完整 / 部分 / 缺失 / 冲突 / 过期 / 不适用`

不得压成一个掩盖缺口的总分。关键数字记录期间、单位、币种、分母、范围、主体和计算方法；口径无法统一时并列展示。

## 工作流

1. 建立三个搜索角度：直接事实、运行机制、当前变化/风险。
2. 写一个可被推翻的初始假设，不把它当结论。
3. 先建证据表，再写报告。
4. 对重要问题完整阅读少量高价值材料，而不是堆链接。
5. 先写判断型标题，确认论证链后再展开正文。
6. 反向从建议追到判断、事实和来源；正向检查关键来源是否被过度解读。
7. 对抗检查主体、时期、样本、币种、分母、相关/因果和隐藏假设。
8. 输出通过、条件通过、未通过或未验证。

## 交付要求

- 先给 3–5 个核心判断，每项带证据、置信度和推翻条件。
- 事实、计算、推断、建议和开放问题分开。
- 冲突来源并存，说明暂时取舍及影响。
- 结论层级不得超过证据层级。
- 缺少关键来源或独立检查时降级结论，不得补写成绿色。
